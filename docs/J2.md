## Situation

Un capteur se tait, une mesure arrive deux fois, une mesure ancienne arrive après une récente, le téléphone perd le réseau.

## Questions à résoudre (à répondre dans ce fichier en fin de J2)

1. Une valeur affichée décrit-elle encore la salle ?
2. Le téléphone est-il déconnecté, ou est-ce l’objet ?
3. Comment reprendre sans doubler l’historique ni remplacer une mesure récente par une ancienne ?

### Réponses

1. **Oui seulement si elle est `fresh`.** La fraîcheur compare `now - observed_at` à `FRESHNESS_MS` (10 s). Si `stale`, la valeur est encore la dernière connue de la salle, mais elle ne décrit plus l’instant présent — l’UI affiche « Donnée ancienne » sans prétendre que le téléphone a perdu le réseau.
2. **Trois signaux distincts :** NetInfo → « Téléphone hors ligne » ; `availability: offline` → « Objet hors ligne » ; `freshness: stale` avec objet `online` → capteur silencieux (ex. `pause`). Un objet en pause reste `online` et passe `stale` après 10 s.
3. **Contrainte unique sur `message_id`** (log `doublon ignore`) ; insertion dans `Measurement` puis **`shouldUpdateLatest`** pour ne pas faire reculer `Device.lastObservedAt` (log `mesure ancienne conservee`) ; historique borné à `HISTORY_LIMIT` (200) après chaque insertion ; côté mobile, cache AsyncStorage consultable hors ligne, un seul polling au retour AppState `active`.

## Travail

### Backend

1. **Borner l’historique** à `HISTORY_LIMIT` (200) par objet : après insertion, supprimer les mesures au-delà de la borne. Documenter dans `docs/decisions/`.
2. **Prouver le doublon** : `docker compose run --rm tools incident sensor-001 duplicate` puis vérifier qu’il n’y a pas deux lignes métier avec le même `message_id` (`GET /api/devices/sensor-001`, logs `doublon ignore`).
3. **Prouver le retard** : `tools incident sensor-001 delay` — l’état courant (`latest.observed_at`) ne recule pas.
4. **Prouver capteur silencieux** : `tools incident sensor-001 pause` — l’objet reste `online`, la mesure passe `stale` après 10 s. L’UI ne doit **pas** dire que le téléphone a perdu le réseau. Puis `resume`.
5. Traces claires : `mesure rejetee`, `doublon ignore`, `mesure ancienne conservee`.

### Mobile

1. **Cache local** (AsyncStorage) : dernières salles + date de mise en cache.
2. **NetInfo** : bandeau « Téléphone hors ligne » distinct de « Donnée ancienne » et de « Objet hors ligne ».
3. Hors ligne : consulter le cache (valeurs + dates). **Pas de file de commandes** (les commandes n’existent qu’en J3 ; si un bouton apparaît, le bloquer avec une explication).
4. **AppState** : à la reprise (arrière-plan → actif), un seul polling, pas de chargement infini, données cohérentes.

Packages Expo : `npx expo install @react-native-async-storage/async-storage @react-native-community/netinfo`
